# 主对话 / 副对话（dsh-master-prompt）

任意会话、任意模式、任意工作区都能开副对话。不需要选择专属模式，也没有整条状态栏；入口只是输入框工具栏里的一个小 `+ 副对话` 按钮。

## 使用

1. 在任意会话的输入框工具栏点 **`+ 副对话`**。
2. 第一次点击会初始化这个会话的总要求（v0），并在**右侧栏**打开一个原生副对话标签；主对话仍在左边。
3. 在右栏副对话里输入任务；可以继续点 `+ 副对话` 开多个标签。
4. 副对话完成后点 **`完成并提交`**（右栏标签头或输入框工具栏），生成总要求变更提案。
5. 主对话工具栏点 **`面板`** 查看提案 / 总要求 / 版本；逐段采纳、直接编辑、回滚都在这里。
6. 副对话工具栏的 **`回主对话`** 切回主对话；**`同步`** 把快照更新到主对话最新版本。

侧边栏不显示 `└` / `+` / `↗` 等插件标记；副对话通过右栏标签进出。

## 存储

每个成为主对话的会话在它的工作区目录下保存：

```
<工作区>/.dsh/master-prompts/<主对话会话ID>/
  prompt.md            当前总要求，可直接编辑
  meta.json            版本号、版本列表、副对话快照映射
  versions/vNNNN.md    每个版本全文
  proposals/<id>.json  提案（pending / superseded / merged / rejected）
```

直接用编辑器改 `prompt.md` 时，插件下一次读取会记为 `external` 版本。

## 命令

- `/master-new`：新建一个主对话并置顶（不再带模式）。
- `/master-child`：为当前会话开副对话。
- `/master-sync`：把当前副对话同步到主对话最新总要求。
- `/master-submit`：让当前副对话生成变更提案。

## 规则

- 副对话只提交提案，不能直接改总要求；主对话可以直接写。
- 副对话只有一层，不能再开副对话。
- 每个会话一份总要求；不同会话、不同工作区互不共享。
- 主对话不读副对话的完整聊天记录，只接收提案摘要。
- 工具按角色暴露：初始化后的主对话有写入工具，副对话只有提案工具。
- 回滚生成新版本，历史不可变。

## 限制

- 总要求越长，每一步都会带上它；建议只放约束和验收标准。
- 提案按「当前总要求」重算差异，并行提案不会硬冲突，但同一段的取舍需要逐段选。
- 副对话基于快照执行，主对话后续修改不会自动推送，需要手动「同步」。
